# 从玩家游玩示范学习情境化的打法偏好

2026-10-14，用户确认：希望亲自玩几场，让系统从游玩记录中理解其打法偏好，例如在某类局面中不必过于保守、倾向继续进攻。目标是理解取舍，不要求逐步模仿用户动作；不由开发者预设稳定通关、速度或资源消耗的优先级。

因此，以用户亲自游玩的记录作为首期偏好学习的数据来源，并将打法偏好与动作复刻分开。相同局面中的不同动作可能符合相同偏好，动作一致率不能单独定义成功。相比要求用户提前写规则或逐条标注，示范降低了教学负担，但对行动动机的推断可能有歧义；不把所有已选动作视为最优，也不把未选动作视为被用户否定。

用户随后确认：每批示范结束后审阅一次约3–5条偏好摘要，可以确认或简短纠正，正常游玩过程不因偏好采访而中断。示范未覆盖的局面允许AI结合已知偏好自行判断，记录下来供事后集中复盘，不将这些判断冒充已经学到的用户偏好。这不等于授权为训练而刻意随机试错。

后续用户接受首版通过战后归纳、审阅和向Jev提供偏好来适配决策，暂不训练独立策略，详见 [ADR 0003](0003-browser-extension-with-external-preferences.md)。用户已确认用留出的完整战斗做偏好前后对照，再通过小规模接管和代表性决策片段判断是否符合已确认偏好；不预设胜率、速度或动作复刻率为首要目标。“玩几场”描述用户期望的教学投入，不代表已经证明该样本量足以学会所有战斗取舍。
